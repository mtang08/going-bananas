## Initial findings and dispositions

1. **TASK-012 completion timing.** The original body required linked status computed by TASK-030, but also expected TASK-012's isolated route to return a computed result. `schemas.md` §7.3 and TASK-012 step 7 now pin `put_completion(session,session_uid,body,*,assess)->SessionCompletion`: mutate/flush, call required assessor, flush, then route commits, refreshes and serializes with `completion_data`. TASK-012 tests inject a fake assessor; production router is unregistered until TASK-030 supplies `metrics.engine.assess_completion`. Commit failure emits no success. No provisional linked `unknown` result escapes.
2. **TASK-012 rollback target protection.** The original body protected only current rows, permitting a target-only historical row to reappear. §7.3 now protects the union of current and target latest revisions, including tombstones, when either revision is historical/locked or completion facts exist. Protected UIDs retain their exact current state, including absence. Mixed future/protected and protected-only fixtures are specified; undo eligibility uses the same predicate.
3. **TASK-012 demo seed shape.** The original `history_edits` format and version count were open. §7.3 and TASK-012 now allow only `{op:'add',session_uid:UUID,fields:SessionFields}`, with explicit unique UUIDs; nonempty history creates version 2, empty history leaves head 1. The Nov 14 UUID42 fixture pins state at versions 1 and 2.
4. **TASK-068 undo replay/head guard.** The original imported-head guard conflicted with identical retry after undo advanced the head. §7.3 adds immutable `legacy_undo_requests` in migration 0012. Under advisory lock, lookup key and compare canonical request hash first; identical replay returns the stored result, changed body conflicts. New keys then enforce imported head/fingerprint; a later request is stale. Same transaction writes inverse version and replay row, including concurrent-key behavior. Import provenance remains immutable.
5. **TASK-068 source preservation.** The original “byte-equivalence” was not a stable PostgreSQL contract. §7.3 names all legacy source tables, includes archived/unmapped rows, defines persisted-column serialization for UUID, timestamps, dates, decimals, floats, bytes, JSONB and nulls, and compares per-row/per-table SHA256 plus counts before and after. It excludes only intentionally changed AppState/new tables.
6. **TASK-068 old writer guards.** Original ownership did not enumerate mutation sites. §7.3 pins `require_legacy_write(session)` before row locks and writes in `core.post_checkin`, `patch_checkin`, `post_plan`, `decide_plan`, `post_completion_link`, `delete_completion_link`, `post_weekly_snapshot`, `coaching._post`, `post_outcome`, and `agent_plans.submit`/`rollback` (with `_persist` assertion). These signatures exist in the baseline. The helper takes advisory lock `71382413`, then plain-reads authority; locks remain through existing commits. Read helper does not mutate.
7. **TASK-068 helper/DB handoff.** §7.3 pins the TASK-065 manifest fields, hashes, `coach_proposal.v1` protocol and manual/calendar authority. Release sequence quiesces writers, verifies backup and artifact, installs and verifies helper, runs read-only schema check, commits DB cutover, then resumes clients. Precommit failure restores old helper with legacy DB; postcommit mismatch keeps services stopped until verified replacement or manager-approved full restore.
