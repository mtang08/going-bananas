## Objective and observable end state
`<CheckinModalV2 request={req} close={fn}/>` renders one of three variants by `req.kind` (default `exception` when `request` is absent): exception check-in (immediate deterministic guidance shown in the modal), post-run RPE (0–10, plus modification reason when the session changed), and delayed-response follow-up (pain yes/no → site, side, severity, timing; gait change). Example: an exception check-in with fatigue 7 posts `{kind:'exception', fatigue:7, …}` and shows "Today's guidance" with the returned decision.

## Implementation procedure
1. Export `export function CheckinModalV2({ request, close }: { request?: CheckinRequest | null; close: () => void })`. `kind = request?.kind ?? 'exception'`. Markup: `<div className="modal-backdrop" onMouseDown={close}><div className="modal checkin-modal" role="dialog" aria-modal="true" aria-label={LABEL[kind]} onMouseDown={e => e.stopPropagation()}>` with `<button className="icon-button close" aria-label="Close" onClick={close}><X/></button>` (`X` from `lucide-react`). `LABEL = {exception:'Record check-in', post_run:'Session RPE', delayed_followup:'Delayed-response check'}`. Every variant has a "Cancel" `text-button` that calls `close`, and shows mutation errors as `<p className="error-text" role="alert">{error.message}</p>`.
2. Shared `SymptomFields({ rows, onChange, defaultTiming })` (local). "Any pain?" = two `<button type="button" className={`choice ${pain === v ? 'active' : ''}`} aria-pressed>` labelled "No" and "Yes" (state `pain: 'no' | 'yes' | null`, initially null). When "Yes", rows start as one `{site:'', side:'left', severity:'', timing: defaultTiming}`; row i fields: "Where?" `symptom-{i}-site` (text, maxLength 60, placeholder "e.g. posterior tibial tendon"); "Side" `symptom-{i}-side` (`SIDE_LABELS`); "Severity (0–10)" `symptom-{i}-severity` (number, min 0, max 10, step 0.5); "When did it start?" `symptom-{i}-timing` (`TIMING_LABELS`); "Remove" when more than one row. Button "Add another site". `symptoms` sent = `pain === 'yes' ? rows.map(r => ({site: r.site.trim(), side: r.side, severity: Number(r.severity), timing: r.timing})) : []`. Validation when yes: empty site → "Enter where it hurts."; severity empty/NaN/outside 0–10 → "Severity must be between 0 and 10."
3. **Exception** variant: eyebrow `CHECK-IN`; `<h2>Something to report?</h2>`; `<p>Report pain, gait change, illness, fatigue, or context. Without a check-in, the planned session stands.</p>`. Fields: "Fatigue (0–10)" `checkin-fatigue` (select: "Not reported" = "", then 0…10); `SymptomFields` with `defaultTiming='unknown'`; "Gait change?" `checkin-gait` ("Not reported" "", "No" `no`, "Yes" `yes`, "Not sure" `unsure`); "Illness" `checkin-illness` ("Not reported" "", "None" `none`, "Possible" `possible`, "Present" `present`); "Context" five toggle `choice` buttons with `aria-pressed`: Heat `heat`, Travel `travel`, Poor sleep `poor_sleep`, Unusual surface `unusual_surface`, Equipment `equipment`; "Note (optional)" `checkin-note` (textarea, maxLength 1000). Submit `className="button primary"` "Save check-in". When fatigue, gait, illness, and pain are all unanswered, and there are no tags and no note, show "Report at least one item." and send nothing. Body: `{kind:'exception', observed_at, fatigue: fatigue === '' ? null : Number(fatigue), illness: illness || null, gait_change: gait || null, context_tags, symptoms, activity_id: request?.activityId ?? null, prompt_id: request?.prompt?.id ?? null, note: note.trim() || null, idempotency_key}` via `post<CheckinV2>('/v2/checkins', body)`. On success: invalidate + `setQueryData` as above; if `daily_guidance` is null → `close()`; else switch to a result view: `<h3>Today's guidance</h3>`, `<span className={`status-chip ${g.decision}`}>{DECISION_LABELS[g.decision]}</span>`, `<p>{g.rationale}</p>`, when `coach_review_suggested`: `<div className="notice warning">Coach review suggested. Run the running-coach skill (daily review) before training.</div>`, when `missing_inputs.length`: `<small>Missing inputs: {missing_inputs.map(statusText).join(', ')}</small>`, and `<button className="button primary">Done</button>` → `close()`.
4. **Post-run** variant (`request.activityId` required; if null render `<p className="error-text">No run selected.</p>`): eyebrow `AFTER YOUR RUN`; `<h2>Session RPE</h2>`; `<p>How hard was the entire session, 0 = rest and 10 = maximal?</p>`. Query `execution = useQuery({queryKey: qk.activityExecution(id), queryFn: () => api<ActivityExecution>(`/activities/${encodeURIComponent(id)}/execution`)})`. RPE: `<div className="choice-grid rpe-grid" role="group" aria-label="Session RPE scale">` with 11 `choice` buttons "0"…"10" (`aria-pressed`), `<small>0 = rest · 10 = maximal</small>`. `changed` = `c = execution.data?.data.completion`; `c != null && c.status !== 'completed_as_planned' && c.status !== 'extra'`. When `changed`: "What changed the session? (optional)" `checkin-reason` ("No reason given" "", then `REASON_LABELS`) and "Reason note (optional)" `checkin-reason-note`. "Anything else? (optional)" `checkin-note`. Submit "Save", disabled until an RPE is chosen. `mutationFn` awaits in order: (a) `put<RpeResult>(`/activities/${encodeURIComponent(id)}/rpe`, {rpe})`; (b) only when `changed` and a reason is chosen: `put<Completion>(`/calendar/completions/${encodeURIComponent(c.session_uid)}`, {expected_version: c.version, activity_id: id, status: c.status, modification_reason: reason, reason_note: reasonNote.trim() || null})`; (c) only when `request.prompt !== null` or the note is non-empty: `post<CheckinV2>('/v2/checkins', {kind:'post_run', observed_at, context_tags:[], symptoms:[], activity_id: id, prompt_id: request.prompt?.id ?? null, note: note.trim() || null, idempotency_key})`. On success invalidate and `close()`.
5. **Delayed follow-up** variant: eyebrow `DELAYED-RESPONSE CHECK`; `<h2>Any pain since this run?</h2>`; `<p>Symptoms can show up 16–48 hours after a longer run. Report what you notice.</p>`. `SymptomFields` with `defaultTiming='hours_24_48'`; "Gait change?" `checkin-gait` ("Choose" "", "No", "Yes", "Not sure"); "Note (optional)" `checkin-note`. Submit "Save". Required: pain answered, else "Answer the pain question."; gait chosen, else "Answer the gait question.". Body `{kind:'delayed_followup', observed_at, gait_change: gait, context_tags:[], symptoms, activity_id: request.activityId, prompt_id: request.prompt?.id ?? null, note: note.trim() || null, idempotency_key}`. On success invalidate and `close()`.
6. In `frontend/tests/app.test.tsx`, delete only the test named above if present.
