The registration and public OpenAPI inventory were compared with FastAPI before retirement. Python remains available for offline historical Alembic upgrades and retained non-HTTP reference tests. The checks below record the synthetic rehearsals. Real workspace deployment follows the owner’s cutover procedure. [Go module](../backend-go) · [Rewrite specification](go-backend-rewrite.md)

## Decisions from running the code

| Question | Result | Implementation decision |
| --- | --- | --- |
| Can both languages consume the existing API schema? | The mounted OpenAPI 3.1.0 schema generated strict Go handlers with `oapi-codegen` v2.9.0 and its runtime v1.9.1. `openapi-typescript` 7.13.0 reproduced the committed TypeScript file byte for byte. Renaming a required field broke compilation of both consumers after regeneration. | Use the native 3.1 document, generated strict interfaces and `net/http`. Pin the tested generators. Validate the status enum explicitly. Go can still construct an invalid zero value or decode an absent nullable field as nil. Test required fields on the wire. [Export command](../scripts/api-types.py) · [Go generator](https://github.com/oapi-codegen/oapi-codegen/releases/tag/v2.9.0) |
| Can the existing schema feed typed Go queries? | sqlc v1.30.0 generated a pgx/v5.7.6 query from PostgreSQL 17.11 DDL. It ran against 52 rows with tied timestamps and a 50-row cap. Changing the sole open draft from pending to stale to invalid verified that all three are included by the open filter. | Use named SQL and pgx. For sqlc input, dump the migrated synthetic schema with `--schema-only --no-owner --no-acl --no-comments --no-tablespaces` and strip the psql-only `\restrict` and `\unrestrict` lines. Use the version-1 backup containing the data and private files for restore. The pilot query counts the JSON changes array, defaults a missing array to zero, filters before limiting, and orders by submission time and UUID descending. |
| Does the Go response actually work for Home? | FastAPI and Go answered 14 requests against the same immutable fixture. Status, parsed JSON, ordering, nulls, timestamp strings, validation field errors and application headers matched after normalizing the random request ID. Home’s real client fetched both listeners. A mounted Home component with React Query displayed the pending proposal and its review link from Go, then removed the card when the fixture became accepted. Other Home requests used existing test fixtures. | Preserve last-value semantics for repeated scalar filters, including invalid/valid permutations. Emit an empty array when there are no items and explicit nulls on nullable dates. The reference emitted timestamps in the database session’s offset and retained six fractional digits when present. Apply these wire rules separately from how hashes encode timestamps. The first component comparison ran in jsdom. The later native candidate passed Chrome checks through the Vite proxy. [Native proposal handler](../backend-go/internal/proposalhttp/handler.go) |
| Does Garmin require Python? | A native Go HTTP probe and Garmin’s Python client 1.0.0 reused each other’s synthetic token cache. The probe exercised expiry, forced renewal and private file permissions. The existing client and app adapter were also tested through mocked HTTP for one retry on 401, propagation of a second 401, `Retry-After` on 429, binary fidelity and repeated-page detection. | Implement the Personal API with `net/http` and test the Go client against the same cases. Use `github.com/muktihari/fit` v0.28.7 for the decoder. Against Garmin’s Python SDK it matched primitive message values on two generated files covering pauses, laps, workout steps, RPE, duplicate records, alternate speed/altitude fields and invalid sentinels. Both rejected damaged CRCs and malformed input. The provider continuation covers app-level normalization and synthetic persisted replay. Live account and device coverage remains a separate check. [HTTP reference test](../backend/tests/unit/test_garmin_http_contract.py) · [FIT comparison](../backend-go/internal/garmin/fit) |
| Can Go preserve historical hash identities? | The stock Go JSON encoder produced different bytes. An offline Go encoder reproduced both typed timestamp formats, their exact bytes and SHA-256 hashes, the existing proposal fingerprint and its revised-content case. A deterministic additional corpus of 11,989 finite floating-point values agreed with Python. | Decode dynamic numbers without first converting all integers to float64. Preserve the integer/float distinction, Python float formatting and UTF-8 string escaping. Include an integer above 2⁵³, negative zero, null, DST offsets and Unicode separators in regression tests. Read a Python-created draft with the finished Go planner before switching writers. ## What the persistence rehearsal changed

- **Bootstrap requires data.** The rehearsal’s Alembic head was `0027_rehab_sessions`. Both a fresh upgrade and a populated upgrade from `0009_agent_plan` produced the same schema. A fresh database also has its Alembic stamp and singleton `app_state` row with id 1, data revision 0 and calendar head 0. The fresh `app_state_id_seq` reported `last_value=1` and `is_called=false`. A new SQL baseline must reproduce the schema, both bootstrap rows and sequence behavior. The current native baseline and historical upgrade checks are maintained separately from this pilot rehearsal. [Upgrade tests](../backend/tests/integration/test_schema_upgrade.py)
- **Compare equivalent catalogs.** PostgreSQL rewrote casts in 68 check/index expression lines when restoring the test dump. Comparing the raw text of an upgraded database against a restored one would report false drift. The fresh baseline and historical backup produced identical schema dumps after the same restore cycle. Compare structured constraints/defaults/index predicates or normalize both through that cycle. Keep sequence and data checks separate.
- **Rehearse failed recovery.** A version-1 archive of the populated synthetic database restored matching rows across all 61 tables, sequence state, allowlisted private files and a referenced raw-object checksum. A damaged dump failed after creating the new targets. The source stayed intact. Retry into fresh targets and verify them before starting the supervisor. Real cutover also needs a verified current backup and a read-only preflight before startup refresh or worker writes. [Backup implementation](../backend/app/services/backup.py) · [Operating procedure](operations.md)

## First implementation results

- A read-only repeatable-read transaction returns the list and data revision from one database snapshot. The Go handler matched FastAPI on 14 requests against a migrated PostgreSQL fixture, including ties, the 50-item cap, repeated filters, empty results, fractional timestamps in a non-UTC timezone, and field-level validation errors. The pilot also checked a single draft as it moved through all three open statuses. The application pins pgx v5.13.0. Upgrading the prototype driver resolved three reachable findings reported by `govulncheck`. [SQL](../backend-go/sql/queries.sql) · [Native handler tests](../backend-go/internal/proposalhttp/handler_test.go) · [Go dependency versions](../backend-go/go.mod)
- A deliberate rename of `change_count` failed the generated-file check. Regenerating the contract then broke both the Go response mapper and React Home at their actual field references. Updating the consumers restored both builds. [Native contract](../backend-go/api/openapi.json)
- Home rendered the pending draft and review link, the empty state, and the failed-list alert in jsdom with both HTTP servers running. The equivalent Playwright check is included. A later native browser run passed against the integrated Go server. [Browser check](../e2e/p0a.spec.ts)
- Settings created a goal in Python, saved an edit through Go, then displayed the updated list from Python using the live Vite proxy and jsdom. The comparison runner exercised 14 edits and errors through both HTTP servers on independent migrated schemas. Both servers returned a field-level 422 for malformed JSON. The parser-reported character offset can differ for an unterminated string. Store tests verify competing versions, the shared advisory lock and rollback when the revision update fails. [Database tests](../backend-go/internal/goals/store_test.go) · [Native goals routes](../backend-go/cmd/going-bananas/routes.go)
- Native Go HTTP tests cover the Garmin token cache, one renewal on 401, rate-limit metadata, activity pagination, per-dataset recovery responses, and downloaded FIT bytes. The installed Python SDK and Go client each reused the other's cache against one local token issuer. Go requires a private cache directory and refuses to change an existing shared directory's permissions. To rerun the SDK comparison after setup, use `GARMIN_SDK_PYTHON="$PWD/backend/.venv/bin/python" make check-go`. The Go FIT decoder matched the Python reference across 30 synthetic archives. The provider continuation verified the native worker and persisted synthetic replay. The Go worker now uses the native decoder. [Go Garmin client and tests](../backend-go/internal/garmin)
