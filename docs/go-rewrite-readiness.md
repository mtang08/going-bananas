# Go rewrite readiness

**Go serves 11 of the 81 HTTP operations in test and demo.** These include proposal and goal lists, goal edits, calendar version history and seven Google Calendar and trip operations. Provider sync enforces the real-mode requirement. The synthetic server can read calendar events and create or edit trips without Google credentials. Native Chrome exercised the Home draft, empty and disconnected states and the Settings goal create/edit/reload flow. Python still creates the goal in this checkpoint. The first-party module also contains the Garmin Personal API client, normalized FIT decoder, coaching fingerprint, plan-to-recording matcher and completion metric identity. FastAPI and the Python worker still serve the athlete. Earlier readiness rehearsals used published `main` at `fc6490c`. [Go module](../backend-go) · [Rewrite specification](go-backend-rewrite.md)

## What the persistence rehearsal changed

- **Bootstrap requires data.** The rehearsal’s Alembic head was `0027_rehab_sessions`. Both a fresh upgrade and a populated upgrade from `0009_agent_plan` produced the same schema. A fresh database also has its Alembic stamp and singleton `app_state` row with id 1, data revision 0 and calendar head 0. The fresh `app_state_id_seq` reported `last_value=1` and `is_called=false`. A new SQL baseline must reproduce the schema, both bootstrap rows and sequence behavior. Re-read the actual head when implementing the baseline. [Upgrade tests](../backend/tests/integration/test_schema_upgrade.py)
- **Compare equivalent catalogs.** PostgreSQL rewrote casts in 68 check/index expression lines when restoring the test dump. Comparing the raw text of an upgraded database against a restored one would report false drift. The fresh baseline and historical backup produced identical schema dumps after the same restore cycle. Compare structured constraints/defaults/index predicates or normalize both through that cycle. Keep sequence and data checks separate.
- **Rehearse failed recovery.** A version-1 archive of the populated synthetic database restored matching rows across all 61 tables, sequence state, allowlisted private files and a referenced raw-object checksum. A damaged dump failed after creating the new targets. The source stayed intact. Retry into fresh targets and verify them before starting the supervisor. Real cutover also needs a verified current backup and a read-only preflight before startup refresh or worker writes. [Backup implementation](../backend/app/services/backup.py) · [Operating procedure](operations.md)

## First implementation results

- A read-only repeatable-read transaction returns the list and data revision from one database snapshot. The Go handler matched FastAPI on 14 requests against a migrated PostgreSQL fixture, including ties, the 50-item cap, repeated filters, empty results, fractional timestamps in a non-UTC timezone, and field-level validation errors. The integration runner also checks a single draft as it moves through all three open statuses. The application pins pgx v5.13.0. Upgrading the prototype driver resolved three reachable findings reported by `govulncheck`. [SQL](../backend-go/sql/queries.sql) · [Full comparison](../scripts/rewrite/test_proposal_slice.py) · [Go dependency versions](../backend-go/go.mod)
- A deliberate rename of `change_count` failed the generated-file check. Regenerating the contract then broke both the Go response mapper and React Home at their actual field references. Updating the consumers restored both builds. [Reproduce the rename](../scripts/rewrite/check_contract_rename.py)
- Home rendered the pending draft and review link, the empty state, and the failed-list alert in jsdom with both HTTP servers running. The equivalent Playwright check is included. Native browser startup was blocked by the macOS execution sandbox in this run. [Browser check](../scripts/rewrite/proposal-home.mjs)
- Settings created a goal in Python, saved an edit through Go, then displayed the updated list from Python using the live Vite proxy and jsdom. The comparison runner exercises 14 edits and errors through both HTTP servers on independent migrated schemas. Both servers return a field-level 422 for malformed JSON. The parser-reported character offset can differ for an unterminated string. Store tests verify competing versions, the shared advisory lock and rollback when the revision update fails. [Database tests](../backend-go/internal/goals/store_test.go) · [HTTP and state comparison](../scripts/rewrite/compare_goals.py)
- Native Go HTTP tests cover the Garmin token cache, one renewal on 401, rate-limit metadata, activity pagination, per-dataset recovery responses, and downloaded FIT bytes. The installed Python SDK and Go client each reused the other's cache against one local token issuer. Go requires a private cache directory and refuses to change an existing shared directory's permissions. To rerun the SDK comparison after setup, use `GARMIN_SDK_PYTHON="$PWD/backend/.venv/bin/python" make check-go`. The Go FIT decoder matched the Python reference across 30 synthetic archives. The live worker still runs the Python decoder. The provider continuation covers ZIP compatibility and persisted replay. [Go Garmin client and tests](../backend-go/internal/garmin)

The later release gates belong to the slices that implement them. Manual calendar completion must exercise rematching, metric refresh, undo and rollback after a refresh failure. Coaching must replay a saved decision receipt and accept or revise an unchanged pre-cutover draft. Ingestion must replay retained files and compare normalized metrics and source history. Normal server startup, phone delivery, worker ownership and recovery after new writes must be exercised before the real switch.
